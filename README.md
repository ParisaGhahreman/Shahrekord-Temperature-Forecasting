# Shahrekord Temperature Forecasting with SimpleRNN and LSTM

This project compares recurrent neural-network models for daily mean-temperature forecasting in Shahrekord, Iran. It evaluates two architectures—**SimpleRNN** and **LSTM**—using input windows of **3, 5, and 10 previous observations**.

> **Reproducibility note:** The notebook contains the modeling and evaluation workflow. The dataset source and usage/license details must be documented before redistributing the CSV publicly. No performance values are stated here because results should be taken from an actual run of the notebook.

## Project objectives

- Forecast the next temperature observation from a sequence of previous temperature observations.
- Compare SimpleRNN and LSTM models with 3-, 5-, and 10-observation lookback windows.
- Evaluate predictions using Mean Absolute Error (MAE) and Root Mean Squared Error (RMSE).
- Save prediction tables, comparison tables, and figures for further analysis.

## Models and experimental setup

Six configurations are evaluated:

| Architecture | Lookback window |
|---|---:|
| SimpleRNN | 3 observations |
| SimpleRNN | 5 observations |
| SimpleRNN | 10 observations |
| LSTM | 3 observations |
| LSTM | 5 observations |
| LSTM | 10 observations |

The notebook uses the following setup:
- Chronological train/test split: first 80% for training and final 20% for testing.
- One-step-ahead test predictions. For each test prediction, the input window uses the preceding **observed** temperatures, including actual temperatures from earlier test dates where applicable.
- A single recurrent layer with 32 units followed by a dense output layer.
- Adam optimizer and mean squared error (MSE) loss.
- Early stopping monitored on validation loss, with patience of 10 epochs and restoration of the best weights.
- Random seed set to 42 for more reproducible experiments.

The notebook compares all six configurations on the dates common to their test predictions. This is important because a fair comparison requires evaluating each model on the same dates.

## Evaluation metrics

- **MAE (°C):** average absolute difference between actual and predicted temperatures. Lower is better.
- **RMSE (°C):** square root of the average squared prediction error. Lower is better and larger errors receive more weight.

The notebook reports the metrics computed from its own run. Model performance can vary across TensorFlow versions, hardware, and nondeterministic operations.

## Notes and limitations

- The workflow treats rows as consecutive observations. If calendar dates are missing, the notebook does not currently insert missing dates or resample the series. Check the date sequence before interpreting each window as consecutive calendar days.
- The evaluation is one-step-ahead using actual previous observations, not a fully recursive multi-day forecast in which earlier predictions are fed back into later inputs.
- The current model uses temperature as its only input feature. It does not include humidity, precipitation, wind, or other meteorological variables.
- A lower MAE or RMSE on this test period does not prove that a model will perform better in all seasons or future periods.
- Add actual results and conclusions only after running the notebook; do not report unverified performance values.
